## 先修 Benchmark

1. 新建 v0.3，不覆盖旧 Gold。按任务定义审阅全部公开改编：TIAGE 的话题变化允许日常闲聊/续接；四道 MAB 虚构关系移出主集、保留旧集诊断来源，换成个人助手的显式知识/状态题。每次改动记录旧 ID、理由和输入/标签是否变化。
2. Memory 允许证据支持的多文件更新和合理 Core 存储；按指定目标的新事实、旧原文移除和其他文件保护计算确定性状态断言，另报动作分。明确这仍不是完整语义 Fact F1。
3. 修正“16 点、21 点截止却强制马上联系”的窗口歧义；新增多候选选择和明确提前窗口，不能仅用截止日猜用户愿意被打扰。
4. 增加单独存放的 30 题挑战集，每 Track 10 题，分开发/保留各 5 题。加入词面误命中、实体取消/条件保留、多文件和候选竞争。实际生成的跨语言与机制变体相关，未实现独立场景家族隔离。保留部分在最终代码冻结后才执行，不声称同一编码 Agent 设计的数据是第三方盲测。

## 再修 Agent

1. Router 在启用模型时只把完整标题识别当作强规则，关键词唯一命中只用于候选排序；不牺牲关闭模型时的兼容规则。
2. Learner 提取阶段提供有界、脱敏的既有主题导航，识别取消/纠正确实涉及已有记忆；先读再决定，不能把 Memory 当新用户证据。选目标避免重复主题，补齐结构化输出示例；来源、路径、唯一片段及 schema 校验不放宽。
3. Attention 使用清晰的实例 JSON 形状，区分 schema 与结果；用开发轨迹核对及时帮助、DND、候选优先级。先不重构管线或增设重试。

## 测评与循环

修复数据和 scorer 后冻结其哈希，先测旧 Agent；再修 Agent 并冻结代码，测同一数据。每一轮先离线契约/回归，再每 Track 三题真实 Smoke，最后正式开发组。轨迹分类至少包括 Benchmark 定义/标注、输入缺失、Agent 提取/目标/整合/校验和不确定语义。

至少完成两次“审阅→修复→测评→归因”循环。只有开发结果和离线回归用于后续修复；最终才运行保留组。若出现新的明确缺陷且预算允许，继续下一轮；连续无可信改善、剩余问题需要人工语义判断或预算不足时停止，不为用完预算重复采样挑最高分。每轮保留原结果、失败、Token 和成本；数据修订引起的得分变化与 Agent 修复收益分开。

所有真实阶段共用一个持久账本，从旧账本安全结转。未知 usage / pending 时停止，SDK 不重试。最终运行全套 pytest、Ruff、构建与 CLI 帮助检查，生成逐题报告和归因队列，提交并正常推送当前分支。
