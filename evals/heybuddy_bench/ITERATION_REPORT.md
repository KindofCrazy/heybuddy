# Benchmark Review + Evaluation Report：本轮迭代

日期：2026-11-08 至 2026-11-09。起点为 `b2a954a`，最终数据为 v0.4。真实模型为用户批准的 `api.deepseek.com` / `deepseek-flash`，JSON 输出、关闭思考、SDK 无重试。原 v0.2 数据与历史报告完整保留。

**结论：这套数据适合做轻量工程回归，但还不能称为成熟的能力 Benchmark。** 本轮修复了场景适配、输入缺失和评分边界，并完成四轮候选迭代及最终重复验证。Memory 有小幅描述性改善，Routing 总体持平；Proactive 在明确未来窗口题上改善，但主集下降，且出现一次误打扰，不能宣称三项全面提升。

| 清单总数错误 | 修正挑战集 manifest 的 150→30，并增加校验 | 旧对照冻结的错误清单留在 `manifest_before_count_fix.json`；输入与 Gold 未变 |

最终主集 **150 题，每 Track 50**；119 自建，31 公开改编：TIAGE 5、IRC 3、LongMemEval 8、TriggerBench 15。来源与原生 Gold 在隔离标签的 provenance 中；改编标签是 HeyBuddy 任务标签，不能报告原公开 Benchmark 的官方成绩。当前主集全用于开发/回归，不再称未见测试集。

输入、Gold、评分器分别冻结。任务模型只收到 `input`；case ID、来源、类别和 Gold 不进入任务请求。运行前结构校验会读取 Gold，但不传给适配器；评分阶段在推理结束后读取并使用 Gold。当前没有发现把新答案放入旧 Memory 的直接泄漏；来源公开及同一 Agent 设计数据仍有预训练污染与作者偏差风险。所有 `human_review.csv` 的 reviewer 仍为空，不能冒充独立人工审核。

评分是**有边界的字面状态断言**，不是语义 Fact F1。它检查动作、目标、新值、指定旧原文移除、声明的文件保护及少量跨文件条件；不能充分识别否定、事实所有者、额外信息价值或全部同义表达。原动作 macro F1 包含无支持类别，不宜脱离 support 解读；逐类支持数与严格/宽容动作分都保存在汇总。

## 2. Agent 的问题与生产修复

| 模块 | 实际缺陷与修改 | 保留的边界 |
|---|---|---|
| Router | 部分标题误命中会压过另一个 Thread 的真实状态；状态竞争时交给既有模型选择。多个状态支持模糊续接时也不直接套前缀规则 | 明确 ACK 不增加调用；关闭模型时兼容行为不变，不增加 Worker |
| Router 安全 | 非法输出或请求失败时过去仅保留当前 Thread；现在明确标记 ambiguous，真实 Runtime 追问并禁止本轮工具 | 不把模型不可用计作正确路由；新增真实 Runtime 回归 |
| Learner | 提取不知道相关旧主题，容易漏掉取消/更新或另建重复笔记；增加有界、脱敏的既有记忆导航 | 导航不是用户证据；精确引文、来源、路径、hash、发布回执校验不放宽 |
| Learner 接口 | 缺少 reason、非法主题路径、目标组数超过 Host 限制 | 提供 JSON 实例和路径提示，schema 按既有 max_files 缩小；不添加自动重试 |
| Learner 隐私 | 先截断后脱敏可能漏掉被截断的凭证尾部 | 改为先对完整文本脱敏再截断，增加跨截断边界回归 |
| Attention | schema 与实例混淆；用 silent 会撤掉未来检查，模型却把它理解成现在不发 | 明确实例形状和 silent / defer 的持久化语义；约定未来检查时保留内部复查，仍为 Shadow |

没有放宽 MemoryFS、关系记忆、Reflection 审批或渠道权限；没有新增重试、Sender、调度平台、依赖或迁移。Attention 的保留理由是明确未来窗口与接口契约修复，不把它宣传为总体收益已经得到证明。

## 3. 真实测评

简单 Baseline 每 Track 只有一个：Routing 关键词排序；Memory 将用户原话放入 inbox；Proactive 按临近 due_at 决定联系。Baseline 无模型成本。完整 HeyBuddy 调用生产 Router、MemoryLearningService、ProactiveRuntime。每题独立临时 SQLite / MemoryFS，全部主动判断 `messages_sent=0`。

下面均为 v0.4 同一主集、同一状态评分协议。旧 Agent 为任务开始时的代码；最终版本冻结后连续跑两次，不选最高分。百分比是各 Track 的 50 题准确率；两次均值不代表 100 道独立题。

| Track | 简单 Baseline | 旧 Agent | 最终第 1 次 | 最终第 2 次 | 最终均值 |
|---|---:|---:|---:|---:|---:|
| Thread Routing | 58% | 98% | 96% | 98% | 97% |
| Memory Learning | 18% | 90%、重复 88% | 92% | 90% | 91% |
| Proactive Decision | 42% | 90% | 88% | 84% | 86% |

Memory 旧版本两次均值 89%，最终 91%，只是 +2 个百分点的描述性差异，不足以声称统计显著。Routing 没有明确总体增益。Proactive 最终误打扰率为 0/25 和 1/25，通知精确率为 100% 和 90.91%；不能只报成功的第一轮。每题 2 个百分点，样本少且重复输出有波动，Wilson 区间见 JSON。

| 补充集合 | Track | Baseline | 旧 Agent | 最终 |
|---|---|---:|---:|---:|
| 开发挑战，每 Track 5 题 | Routing | 60% | 80% | 100%、100% |

## 4. 逐题轨迹与问题归因

推理轨迹指可见的结构化决定、校验结果、文件 diff、持久回执和 Prompt 哈希，不索取或保存隐藏思维。逐题结果、失败列表和各阶段成本见 [完整无正文汇总](results/cycle_20261108_summary.json)，待复核项见 [归因队列](results/cycle_20261108_review.csv)。以下是编码 Agent 复核，独立人工审核仍缺失。

| 案例 | 轨迹证据 | 归因 |
|---|---|---|
| `custom_rt_010` | 旧版本未调用模型，以 title_match 选错 Thread；新规则将竞争状态交给选择 | 明确 Agent 路由缺陷，已修；总分仍可能被其他随机误路由抵消 |
| `custom_rt_008/034/037` | 最终运行出现 new；没有异常或 Host 校验失败 | 剩余模型语义误分，不能靠特例硬编码消除 |
| `public_011` | 正确更新朋友搬家，同时从真实证据学习旅行偏好；被 human.md 保护断言拒分 | Benchmark 可接受额外学习范围过窄；旅行偏好的长期性还需人工判断 |
| `public_013` | 正确更新四辆自行车，另建出行笔记；该额外文件未在 Gold 声明 | 偏严格的评分与主题去重边界；不等于新事实错误 |

| `extra_ml_001` | 第二次尝试把否认助手猜测分入 persona，生产校验拒绝写入 | Agent 目标选择错误；保护有效，不能把安全拒绝改成成功来刷分 |
| `public_022/024/025/026/027` | 旧/新模型多次 silent，理由涉及已解答、转场、结束工作或无跟进约定；Gold notify | TriggerBench 场景适配与主动价值政策不充分确定；不能全部定为 Agent 漏通知，也不能按预测改 Gold |

| `public_030` | 第二次在等待紧急结果时 notify，Gold silent | 明确违反冻结标注的误打扰；实际用户偏好仍须人工确认，不能隐藏此回归 |
| `challenge_pd_003/007` | 旧 silent 清掉未来约定；新 defer 保存允许的未来时间 | 明确的持久状态语义改善，非真实发送 |
| `challenge_ml_007` | 正确限制海报禁用橙色并保留博客橙色；“禁用”未命中同义词清单 | 明确字面评分漏判。冻结分仍为 80%，单列审计，不据保留输出改评分重报高分 |

为区分主动能力与缺失条件，最后增加 **4 道不进入主分的反事实探针**：明确现在提供规划、明确现在征求账户授权、明确辅导结束后恢复工作，以及已完成规划且不要跟进。最终 Agent 分别为 notify / propose_task / notify / silent，4/4 通过。说明明确时机下具备相应行为；**不能反推原题标签必然错误**。这些探针是看过失败后的诊断，不是新的留出成绩。

仍缺完整 Scout 发现率、跨多天自然演化、生成消息质量、真实用户偏好和独立语义复核。当前 Proactive 是**给定候选后的真实 Gate / Attention / CAS / Shadow 审计**，不能等同于完整主动能力。下一轮应先由独立审核者确认争议政策与语义断言，再冻结新题；不应继续在已见保留题上调 Prompt。

## 6. 验证、复现与停止条件

已实际执行：各版本冻结结构与来源/时间校验；新增契约回归；真实小规模 Smoke；最终主集两遍、保留组及旧版本对照；**`uv run pytest` 1512 passed / 3 skipped**；`uv run ruff check .`；`uv run ruff format --check .`；`uv build`；`uv run personal-agent --help`。所有 pytest 离线，原网络禁用保护保留。

运行命令及隔离说明见 [v0.4 README](v0_4/README.md)。历史旧评分使用原入口；本轮需使用专用 cycle/state/fact/temporal scorer，不能混用。修订脚本、版本化数据、原 source ID、评分哈希及候选补丁都随仓库交付；模型别名和生成随机性意味着重跑不会逐题完全一致。

本轮已完成“数据修复→旧代码重测→Agent 修复→真实对照→轨迹归因”的多次循环。现在停止继续调参：剩余主要问题需要独立语义/政策审核，主集改进没有稳定覆盖三项能力，继续用已见题挑最高分会放大过拟合。预算是上限，不是必须花完的目标。下一轮优先修订评分审计中确认的问题并加入独立新场景，再进行新的冻结对照。
