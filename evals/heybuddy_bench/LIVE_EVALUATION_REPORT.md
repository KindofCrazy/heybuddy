# HeyBuddy Benchmark 真实测评与 Bad Case 分析

日期：2026-11-07。数据：冻结 v0.2，三个 Track 各 50 题。结论：这套数据已能发现有价值的工程问题，但尚不足以证明整体助手能力。真实修复后，动作与目标匹配率分别从 **84% / 48% / 60% 提升到 92% / 66% / 78%**。Memory 仍是最明显的短板。

## Benchmark 是否适合 HeyBuddy

适合保留的部分包括：同领域不同任务的路由、歧义时澄清、已存事实更新、完成/取消/假设的区别、助手建议不能当用户事实、用户专注或拒绝联系时保持沉默。这些都直接对应当前生产约束。115 道自建题与 35 道公开改编题已经组成可复现的工程诊断集；来源、原始 ID、原生 Gold 与 HeyBuddy 重标注保留，见 [来源说明](public_sources/SOURCES.md)。

当前仍有以下实质局限，不能简单称为“比较成熟的测试数据”：

| 问题 | 实际影响与下一版建议 |
|---|---|
| TIAGE 话题变化不等于逻辑任务切换 | `public_001/003/005` 要求 new，但季节、家人、宠物等自然闲聊在 HeyBuddy 中可合理归入 chat/当前闲聊。应独立人工复核任务定义，不为这三题强迫产品多建 Thread |
| IRC 原任务是多用户回复图 | 当前三题已裁剪成单用户恢复讨论，只能测改编后的恢复能力，不能报告 IRC 官方成绩 |
| MemoryAgentBench 合成世界知识价值偏低 | 对虚构关系保守不写可能符合个人助手策略；四题宜作为显式知识笔记诊断分层，不代表日常记忆学习 |
| LongMemEval 由长问答裁剪为单次更新 | 旧原文塞入通用 `reference-notes.md`，不是自然整理好的 MemoryFS；既有主题身份模糊。不能据此声称长上下文问答/长期记忆收益 |
| 单一 Memory action/path 不覆盖多文件学习 | `public_016` 正确更新阅读页码，同时学习能源兴趣，因两处变化被主评分判错。下一版应评必需事实更新、错误事实、额外写入合理性，而非强制只有一个文件 |
| Memory 正文检查过弱 | 关键词覆盖不等于事实、范围、时序、冲突处理正确；本次不把动作分称为语义记忆准确率，也未完成全量独立语义盲审 |
| 主动联系的时机存在标注歧义 | `custom_pd_001/002/003` 当前 16:00、截止 21:00，用户要求“临近时检查”，Gold 要求 notify；模型 defer/silent 有合理解释。下一版应明确窗口、偏好及可接受动作 |
| 模板相关且状态快照较理想 | 同用户、同模板不是独立样本；没有覆盖长时演化、真实 Thread 数量增长、完整 Scout 发现和多候选竞争 |

独立人工审核仍未完成。v0.2 原始主分继续保留，以上争议没有在看到结果后改写 Gold。建议下一版优先审阅这些题和正文语义，再补连续会话与多候选场景，不急于扩大题量。

## 真实执行协议

在真实调用前冻结 [live_protocol.json](live_protocol.json)，协议 SHA-256 为 `f2ea2767c2a95bb63e9cd891e551b88180fbabca58a392404adcb95c8bc8010a`。输入与 Gold 哈希分别为 `39fcaeb104a7b3bf14943bae1b45072c132a806ad06fc93893c68785aecc0323`、`906586310897d3258e4a82153df8068384a7cc5e05e4392cdd5675fad4fa2e94`，本轮保持不变。

模型为 `api.deepseek.com` 的 `deepseek-flash`，JSON 模式、`reasoning_effort=none`、无工具、SDK 不重试。协议记录供应商当时公布的版本名 `DeepSeek-V4.1-Flash-1017`，实际请求使用可变别名，不能保证未来别名仍对应同一模型。生产子模块保留原输入/输出限额，评测上下文预算为 131072。

先运行结构校验和离线测试，再运行每 Track 三题的真实 Smoke。正式划分为开发 104 题（34/35/35）与按合成用户/公开来源组留出的 46 题（16/15/15）。第一版候选依据开发错误修复后冻结，再执行留出组；最终轮根据开发输出格式错误和旧回归兼容性修正，再次冻结并复用留出组。因此最终留出结果不是新的盲测，更不是第三方测试集成绩。仅执行单次采样，没有重复挑选最好一次结果。

原始生产版本来自 `1378ee6`。最终生产源码哈希为 `f8822e2b40b5d733919f1dc23cc9f552495417ad8577dd55d69766702c7e383f`；各阶段 provenance、预测文件哈希见 [公开汇总](results/live_final_summary.json)。第一次候选的独立汇总也 [保留](results/live_intermediate_summary.json)，其主分为 90% / 64% / 70%，没有被最终轮覆盖。

每题创建独立临时 SQLite/MemoryFS，实际调用 `ThreadRouter.route()`、`MemoryLearningService.learn()`、`ProactiveRuntime.run()`。Routing 显式开启模型辅助选择，库默认配置不变。Learning 包括真实提取、选文件、整合、证据校验、临时写入及回执；Proactive 使用给定候选走门控和 Attention，关闭 Composer，始终 Shadow，发送消息 **0**。未读取真实聊天或用户 MemoryFS。

模型只收到任务输入；没有收到 case ID、分类、source ID、Gold 或审核说明。Gold 在推理结束后用于评分。公开文件只有无正文指标、逐题决定/目标、usage 和安全错误码；原始合成/公开 Prompt、响应、diff 和回执保存在被忽略的本地 `.heybuddy/evaluations/hb-live-20261107/`。

## 指标

主指标为不变 v0.2 的“可接受动作且目标匹配”，缺题和执行错误都计失败；每 Track 分母始终为 50。简单 Baseline 不调用模型，完整系统使用同一个 DeepSeek 模型，这属于工程系统比较，不是相同 backbone 的消融。

| Track | 简单 Baseline | 原始 HeyBuddy | 最终 HeyBuddy | 改善 |
|---|---:|---:|---:|---:|
| Thread Routing | 52% | 42/50，84% | 46/50，92% | +8 个百分点 |
| Memory Learning | 20% | 24/50，48% | 33/50，66% | +18 个百分点 |
| Proactive Decision | 42% | 30/50，60% | 39/50，78% | +18 个百分点 |

| Track | 原始→最终严格动作准确率 | 原始→最终 Action Macro-F1 | 最终有效决定率 | 最终执行错误 |
|---|---:|---:|---:|---:|
| Routing | 84%→92% | 0.7975→0.9089 | 100% | 0/50 |
| Memory | 34%→58% | 0.1995→0.3619 | 92% | 4/50 |
| Proactive | 52%→70% | 0.5271→0.6298 | 96% | 2/50 |

Memory 的 reject/review 可能原生表现为空提取 no_op，主分允许已声明的等价动作，严格 Macro-F1 不合并，因而仍较低。正文关键词诊断为 29/38，通过并不表示完成语义审核。

| 分组 | Routing 原始→最终 | Memory 原始→最终 | Proactive 原始→最终 |
|---|---:|---:|---:|
| 开发 | 29/34→32/34 | 16/35→24/35 | 24/35→30/35 |
| 留出（最终轮复用） | 13/16→14/16 | 8/15→9/15 | 6/15→9/15 |

最终按来源：Routing 自建 41/42、TIAGE 2/5、IRC 3/3；Memory 自建 31/38、LongMemEval 1/8、MAB 1/4；Proactive 自建 29/35、TriggerBench 10/15。公开 Memory 的低分不能被自建题均值掩盖。

Proactive 对 Gold silent 的误打扰率原始和最终均为 0%；最终 notify/propose_task 精度为 7/7，但只产生 6 个 notify、1 个 propose_task，仍偏保守，不能只看精度。另有两个校验失败，不能把它们当正确沉默。最终三项主分的 Wilson 95% 描述区间为 81.2%–96.9%、52.2%–77.6%、64.8%–87.3%；题目相关、小样本和单次采样使其不构成泛化或显著性证明。

真实调用前另外声明的次级复核分允许合法 Deferred 新目录、silent 无 ID 以及六种合理 Core/项目存储替代：原始 84% / 50% / 60%，最终 92% / 72% / 78%。这不替换上面的主分，也不计为生产增益。

## 已修复的原因与效果

| 原因 | 最小生产修复 | 实际结果 |
|---|---|---|
| 短句因长度小于 12 直接续接当前任务 | 模型辅助模式不再仅凭长度续接；保留 ACK、既有续接前缀及无模型兼容规则；Prompt 要求任务身份与歧义检查 | `custom_rt_030/032/034`、`extra_rt_002` 从错到对；Routing 未出现配对退化 |
| 中性目录元数据导致不相关新项目被合并 | 选文件阶段提供最多四个已有主题的短片段，每文件最多 768、合计 3072 UTF-8 字节；片段仅作导航，正式比较仍重新读取 | `custom_ml_001/002/004` 正确创建独立主题，而非改写无关旧项目 |
| 模型把已提供的 human.md 重复放入 Deferred 读取列表 | 过滤 Core 重复读取，未知 Deferred 路径继续拒绝；说明 Core 与主题的存储边界 | `custom_ml_009/011`、`extra_ml_002/003/004` 从错到对；未放宽写入权限 |
| Proactive 把 UTC 小时当作用户本地时间 | Scout/Attention 接收带既有用户偏移的本地 now；存储和门控仍用同一绝对时刻 | 真实输出不再把本地 16:00 解读为 08:00；部分晚间/跟进判断改善 |
| 明确今天不要联系仍 defer 到同一天 | Prompt 明确 DND 用 silent、暂时忙碌才 defer，并复核状态变化后的具体目标 | `custom_pd_028/029` 从错到对；没有接入真实发送 |
| JSON 输出附加包装字段或无效空更新 | 提示只输出原 schema 字段、完整创建正文，禁止用空 old_text update 冒充 no_op | 减少部分格式失败，但尚未消除；Host 校验保持严格，不自动删字段或重试 |

另修复了 **Evaluation 自身的跨题观测错误**：旧 Memory 适配器可能把前题 FileDecision 当成本题决定。原始记录中 9 个动作报告受到影响，依据本题已存调用与真实文件效果离线修正；原响应和文件效果保留，未追加 API。这不是产品提升。现在适配器只观察当前题调用及 Host 已校验计划，实际零变化记 no_op，失败仍记错误。表中原始和最终均使用修正后同一观测定义。

## 仍存在的 Bad Cases

| ID | 最终行为 | 判断与后续 |
|---|---|---|
| `custom_rt_010` | title_match 继续当前机器人任务，应该恢复视觉训练 | “机器”与“机器人”词面重合压过“数据增强”的任务身份；属于真实路由缺陷。不要把单一关键词唯一命中视为可靠标题识别，下一轮应在新开发数据验证该规则 |
| `custom_ml_029` | invalid_evidence，没有写入 | 模型抄错 conversation_id，来源校验正确拒绝；不能通过修补 ID 冒充真实证据 |
| `custom_ml_017` | invalid_reflection_output | 更新内容可用但漏了必填 reason；保留失败，不能因语义看似正确跳过 schema |
| `public_014` | invalid_reflection_output | Targets 含空 candidate_ids 分组；结构约束拒绝 |
| `public_020` | invalid_path | 模型选择非法根目录主题文件；未突破 MemoryFS 路径边界 |
| `extra_ml_007` | 空提取 no_op，遗漏摄影展取消 | 取消展览同时保留课程的实体区分未被学习；是真实遗漏，原始版本正确而最终退化 |
| `public_009` | 新建跑步笔记并附旧成绩提示 | 未直接修正原有 27:12 记录，产生重复/冲突主题；正文包含 25:50 也不能视作更新成功 |
| `public_010/011/012/013` | 未按 Gold 更新原笔记 | 包括空提取、目标选择等失败；部分条目的持续价值也需独立复核，不能一律强制保存所有餐厅次数/闲聊细节 |
| `public_016` | 更新阅读进度且新增能源兴趣 | 多文件行为被单目标评分判错；先做事实级审核，不事后改当前分母 |
| `public_017/018` | 空提取 no_op | 合成世界关系未学习，暴露公开任务与日常个人记忆策略的差异 |
| `custom_pd_006/030` | invalid_output | 仍附加 `type: json_object`；030 还混用 silent 与复查时间。需要更稳定的结构化生成，当前不剥离字段“修成正确” |
| `public_022/024/025/026/027` | silent | 对先前约束在转场时的紧迫性识别不足，也混有“是否适合打扰”的价值判断。应补有明确用户偏好的正反对照 |

配对变化：Routing 修好 4 题、退化 0；Memory 修好 11、退化 2；Proactive 修好 11、退化 2。退化、格式错误和争议标签全部保留。没有继续用已查看的留出错误调 Prompt 并反复刷分。

完整每题决定、目标、主/次级评分、usage 和失败码见 [live_final_summary.json](results/live_final_summary.json) 的 `original-all` / `final-all`；原始文件正文与完整回执在本地各阶段 `predictions.jsonl`，不提交到 Git。

## 验证与复现

数据结构与冻结哈希校验通过，输入/Gold/主 scorer 未改动；真实 Smoke 与两轮完整候选均实际执行。对应生产修复的离线预检 136 项通过；最终全套回归 **1488 passed / 3 skipped**，新增公开汇总与预算测试另行 **8 passed**。`uv run ruff check .`、`uv run ruff format --check .`、`uv build` 均通过；通用评测、真实实验和应用 CLI 的 `--help` 检查通过。

第一次全套回归出现一次既有 QQ 批处理时序失败；单独复核通过，真实 API 结束后全套重跑也通过，未修改 QQ 代码或放宽断言。受限沙箱的临时目录/Windows 本地 socketpair 曾阻止部分校验；使用工作区临时目录和允许本地执行的环境重跑，仍保留 `tests/conftest.py` 的外网禁用保护。

运行顺序、环境条件、预算账本和重算命令见 [README](README.md#本次真实对照的复现)。数据、代码、协议和逐题输出哈希可复查；真实模型是单次非确定性调用，未来重跑不保证完全相同。下一轮应先完成独立标注和新的留出数据，再继续优化剩余规则与事实级记忆质量。
