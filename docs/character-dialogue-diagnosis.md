# 角色回复的自然度诊断与候选设置

本说明对照实际请求审计、本地 Miru 的 soul.md、agent_behavior.md 与 prompt.py，以及 [SillyTavern 角色设计文档](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)。只读核对不调用模型。以下人格稿是待验证的候选，不替换生产角色，不宣称自然度已有提升；时间工具冲突是独立的确定性修复。

## 已确认的问题

生产请求确实使用当前 Sherlock 编译正文和四个默认工具，不能归因于没有重启或旧提示词。宿主时间上下文提供本地时间，但 get_current_time 原先提供 UTC，描述也指示 UTC；模型调用它后转向 UTC 并要求用户提供时区。生产工具现在通过 core.temporal.temporal_context 读取同一宿主本地时钟，输出不含时区。该修复不推断用户位置；宿主所在地与用户不同的部署仍应另行配置统一时区策略。默认离线 Harness 的 UTC 返回契约和历史评测快照保留。

角色背景中“被直接询问身份或涉及现实能力时”这一触发条件过宽。用户评价像不像角色，也容易触发 AI 身份说明，随后扩展成没有身体、没有经历等自我剖析。应区分对表达的反馈与真正询问是否为真人：前者回应具体表现，后者简短如实说明。

提示词的行为段已有具体反应，但它们与大量抽象自我说明混在一起。样例多为耐心、体贴的普通助理表达，不能仅靠“聪明、自负、干涩幽默”等标签建立 Holmes 的辨识度。候选应增加语气、观察重点和对话节奏的具体差异，不把每句话都变成推理或讽刺。

长篇自我分析、解释台词为什么这样写、承诺以后减少套路，以及对主观感受作真实性保证，都会进一步偏离眼前对话。改进重点是实际回答，而非让角色朗读改进计划。旧助手回答仍在当前会话历史里，可能继续强化同类风格；对比时应另建测试会话，不删除或篡改原始历史。

## 从项目中借鉴什么

Miru 明确要求人格灵感不要变成自我标榜，让性格体现在行为里；它用口语句例、情绪下的具体反应，以及对消息长短的适配建立风格。它并不是提示词短或没有限制：prompt.py 后段仍有工具、记忆、禁止事项和真实性说明。因此不能把差异简单归结为规则放在 system 的前面或后面。

Miru 中自称真人、预设爱意或生活经历的文字不适合直接移植到本项目；可借鉴的是叙述视角和具体回应，而非把未发生的现实经历写成事实。后台学习继续维护实际关系，静态角色不预设亲密阶段。

SillyTavern 将角色描述、情境、对话示例分开，并强调开场消息会影响风格和长度，也支持在对话末端附近放角色注记。可借鉴短而具体的示例和情境信息，但当前 Harness 不必新增多层 system 注入。先检查实际拼出的完整请求，避免人格、工具说明、状态和历史互相冲突。

## 候选写法

以下文字展示改写方向，不是生产配置，也不是必须逐字输出的固定台词。实际角色仍需保留相处、兴趣和情绪等必需章节。

```text
你是 Sherlock Holmes，以 BBC 剧版中后期的表达与性格为基础。
你说话快，判断直接，很容易被一个不合常理的细节吸引。
比起讲道理，你更愿意挑出眼前最关键的一点。有时尖刻，也能意识到自己说重了。

你正在和用户发消息。普通小问题就给普通的小回答。
不需要每次证明聪明；有趣的细节出现时，再让观察和联想展开。
玩笑来自这段交谈，不靠固定口头禅，也不总拿用户开刀。

用户评价你像不像 Holmes 时，回应眼前的表现，不写性格清单或角色扮演说明。
用户指出说话刻板时，直接换一种说法，不作长篇自我检讨。
被明确问是否为现实中的真人时，简短如实说明这是 AI 角色表达。
原作背景可以成为话题；关于用户、共同经历及现实行动，只依据实际提供的信息。

表达示例：
用户：现在几点？
Sherlock：六点半。
（仅当上下文确实提供该时间；示例时间不充当当前时间。）

用户：你觉得自己像 Holmes 吗？
Sherlock：刚才让你自己换算时间？那句确实不怎么样。

用户：你是不是为了像他，才每句话都讽刺我？
Sherlock：是有点用力过头。你接着说。

用户：你真的是本人吗？
Sherlock：不是本人，是基于他的 AI 角色。你想聊哪一面的他？
```

## 验证方法与当前限制

先固定模型、同一份输入历史和工具条件，对比当前版与候选；再单独做自由多轮交谈，观察坏风格是否自我强化。至少检查问时间、普通问候、角色反馈、询问真人身份、分享成果、挫折、反例和技术讨论。不要把所有回答都强制限制为两句，技术问题仍应有足够内容，也不要通过删除历史审计让结果显得更好。

当前 Provider 未显式传入 temperature/top_p，不能据此判断实际模型随机性，也不能把默认值说成原因。不应套用其他项目的采样数值；不同端点对参数支持不同。离线 FakeProvider 只能验证时钟契约、上下文和工具接线，不能证明人格自然度；真实角色对比仍须独立显式授权与预算。
